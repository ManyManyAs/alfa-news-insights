# План разработки «Бизнес-радара» (v2)

> Исходная точка — **v0.1** в `main` (коммит `f8836c1`): работающий сквозной сценарий в mock-режиме, 14 тестов, CI зелёный, Docker собирается.
> Цель — не «закрыть требования», а сделать продукт, после демо которого жюри хочет им пользоваться: глубокая персональная аналитика, видимая позиция банка, прозрачный AI и красивый, быстрый интерфейс.

## Этап 0. Фундамент и процессы

1. Доступ жюри: Settings → Collaborators → `alfa-hack-2026`.
2. Правила работы: ветки `feat/*`, PR с обязательным зелёным CI, шаблон PR (что сделано / как проверить / метрики до-после), GitHub Projects-доска с задачами из этого плана.
3. Инструменты качества кода: `ruff` (lint+format), `mypy` для `app/`, `eslint` + `prettier` для фронта, pre-commit-хуки.
4. Сгенерировать `uv.lock` на машине команды (в дополнение к `requirements.lock`), закоммитить.
5. Сервер: бесплатный/дешёвый VPS (Yandex Cloud / Timeweb / Fly.io), домен, HTTPS через Caddy, автодеплой `main` из GitHub Actions (build → push image → ssh deploy), отдельный стенд `staging` для PR.
6. Вопросы организаторам (отправить сразу): id моделей и формат API (OpenAI-совместимый? JSON-mode? vision? function calling?), разрешены ли локальные embedding-модели, какие источники новостей можно парсить, формат защиты и будет ли «чужая» новость от жюри.

**DoD:** PR → тесты + eval-отчёт комментарием в PR → автодеплой на staging; прод доступен по HTTPS.

## Этап 1. Живой LLM-слой

1. Подключить ключ, прописать реальные id в `config/models.yaml`, проверить каждую модель: JSON-mode, vision (Qwen3-VL), длинный контекст (Kimi), скорость и стоимость.
2. **Бенчмарк моделей** на 20 задачах каждого типа (классификация, интерпретация, критик) → таблица «качество / цена / латентность» → обоснованный роутинг (идёт в презентацию).
3. Надёжный структурированный вывод: JSON-схема из pydantic в промпте, валидация, авто-ремонт (повторный запрос с текстом ошибки), лимит попыток.
4. **Двухуровневая генерация** (главная экономия):
   - *event-level* (один раз на событие): что произошло, факты/прогнозы, каналы влияния по факторам, позиция банка → кэш;
   - *client-level* (на клиента): только персональный слой поверх event-level — короткий дешёвый промпт.
5. Стриминг (SSE): прогресс агента «планирую → ищу позицию банка → проверяю» и потоковые ответы чата.
6. Бюджет-менеджер: прогноз расхода на день, приоритеты (открытые пользователем карточки > демо-клиенты > фоновый предрасчёт), ночной предрасчёт топ-событий для демо-учёток.

**DoD:** live-режим на 30 событиях × 6 персон без ошибок парсинга; средняя стоимость персонального инсайта и p95 латентности зафиксированы в `docs/QUALITY.md`.

## Этап 2. Знания банка — сделать позицию банка «главным героем»

1. OCR всех 64 страниц (`scripts/extract_bank_theses.py`), вычитка таблиц и чисел вручную (это фундамент доверия).
2. Извлечение тезисов Kimi-K2.6 → ревью → расширить базу с 28 до **80–120 тезисов**; схема тезиса + тип (`прогноз | оценка | рекомендация | риск`).
3. **Структурированный макропрогноз банка**: таблица `indicator, value, period, doc_id, date` (ставка, инфляция, ВВП, курс, безработица, зарплаты…) + инструмент `get_bank_forecast(indicator)`. Агент использует числа банка, а не придумывает свои.
4. **Эволюция позиции**: если банк менял прогноз — показывать «банк повысил прогноз ставки на конец 2026 г. с 13,5% до 14,0% (05.08 → 11.09)».
5. Графики из PDF: описание Qwen-VL + привязка к странице → в карточке «смотреть график в отчёте» (превью страницы PNG).
6. Поиск: BM25 + эмбеддинги (если разрешат) + LLM-реранк; размеченный набор 40 вопросов «событие → нужный тезис», метрика recall@5.
7. Режим «нет позиции банка» остаётся честным, плюс ближайший релевантный тезис с пометкой «косвенно».

**DoD:** recall@5 ≥ 0,85; на событиях 5 тематик (ставка, курс, налоги, сырьё, потребление) агент цитирует банк с документом и страницей.

## Этап 3. Данные клиента и граф — углубить персонализацию

1. Миграция на PostgreSQL (+ pgvector при эмбеддингах), Alembic-миграции.
2. **Полный граф**: компании + физлица + группы. Аффилированность через общих физлиц, центральность, сообщества; отраслевой профиль цепочки поставок (доли закупок/продаж по отраслям), концентрация (HHI), география контрагентов.
3. **Эффекты второго и третьего порядка**: «событие → отрасль вашего ключевого покупателя → ваша выручка». Отдельный тип причины в ленте.
4. **Похожие компании и бенчмарки**: кластеризация по признакам → «компании вашей отрасли и размера чаще используют…», холодный старт для «бедных» профилей.
5. Оценки чувствительности в деньгах (явно как оценки): ФОТ по численности и отрасли, валютная экспозиция по ВЭД, процентная нагрузка — с вводом суммы долга пользователем (см. этап 6 «что если»).
6. Отчёт о качестве данных по компании и по датасету (дубли, заглушки, пропуски) — в UI профиля и в документации.

**DoD:** в профиле видна цепочка «вы → ключевые контрагенты (отрасли, доли) → их чувствительность»; ≥ 30% инсайтов демо-персон содержат причину из графа.

## Этап 4. Живой поток новостей

1. 12–15 источников: ЦБ, Минфин, Минэкономразвития, Росстат, MOEX, Интерфакс, ТАСС, РБК, Коммерсантъ, Ведомости (заголовок+лид), отраслевые СМИ (стройка, ритейл, логистика, IT, агро, металлы). Монитор здоровья источников.
2. Предфильтр шума (спорт, светская хроника) правилами до LLM.
3. Извлечение сущностей: регионы, страны, отрасли (→ ОКВЭД), суммы, **даты вступления в силу** (для регуляторики → «через 42 дня вступает в силу»).
4. Дедуп v2: MinHash-LSH + LLM-арбитр для пограничных пар; **сюжеты** — цепочки связанных событий с таймлайном (сигнал ЦБ → решение → реакция рынка ОФЗ).
5. Доверие к источнику (официальный > агентство > СМИ), противоречия между источниками показываются явно.
6. Региональность: региональные новости → компании региона.
7. Классификатор v2: разметка 200 новостей, F1 по факторам ≥ 0,8, точность направления ≥ 0,85.

**DoD:** сервис 24/7 собирает поток; классификация ≤ 30% дневного бюджета; дедуп precision ≥ 0,9 на 100 парах.

## Этап 5. Персонализация v2

1. Признаки ранжирования: вес фактора, уверенность, важность, свежесть, регион, граф, новизна сюжета, роль, реакции пользователя.
2. LLM-реранк топ-15 (Gemma) + сравнение с базовым скорингом на разметке.
3. **Разнообразие ленты** (MMR): не пять новостей про ставку подряд — сюжет сворачивается в одну карточку.
4. «Тишина — тоже ответ»: если важного нет — так и сказать, с последним значимым событием.
5. Обучение на фидбеке: 👍/👎 и «неактуально, потому что…» корректируют веса факторов компании (персональный оверрайд профиля).
6. Learning-to-rank (LightGBM) — когда наберётся разметка 300+ пар.

**DoD:** nDCG@5 ≥ 0,9 и P@3 ≥ 0,9 на расширенной разметке; ручная проверка лент 6 персон экспертом.

## Этап 6. Агент v2

1. Новые инструменты: `get_bank_forecast`, `get_peer_benchmark`, `get_story_timeline`, `get_group_view`, `get_regulation_dates`, `scenario_calc`.
2. **Сценарии**: базовый (= позиция банка) / негативный / позитивный, с триггерами «что изменит вывод».
3. **«Что если» без LLM**: детерминированный калькулятор — ставка ±1–3 п.п., курс ±10–20%, рост ФОТ; пользователь вводит сумму долга или долю импорта → мгновенный пересчёт эффекта.
4. Критик v2: LLM-as-judge по 5 осям (персонализация, глубина, обоснованность, позиция банка, конкретность действий), порог 4/5 → правка; правила-критик остаётся первым фильтром.
5. Уровни уверенности на каждом выводе и блок «что может изменить вывод».
6. **Прогрессивная выдача**: главный вывод через 1–2 с (из скоринга и event-level кэша), полный разбор догружается стримом.
7. Ограничители: таймаут, лимит итераций и стоимости на запрос, все отказы видны в трассировке.

**DoD:** средняя оценка LLM-judge ≥ 4,2 и экспертная ≥ 4/5 на 30 инсайтах; 0 неподтверждённых чисел в фактах.

## Этап 7. Продукт и дизайн — чтобы было «вау»

**Технологии:** React + TypeScript + Vite, дизайн-токены (цвет, типографика, отступы, радиусы), компоненты на Radix/shadcn-подобной базе, иконки Lucide, графики (Recharts/ECharts), анимации Framer Motion, тёмная тема, сборка в Docker multi-stage. Визуальный язык — чистый B2B-банк: белые поверхности, один акцентный цвет, крупная типографика ключевых выводов, без лишних рамок.

**Экраны:**
1. **Главная интернет-банка** с виджетом «Бизнес-радар»: 3 главные карточки, бейдж рисков, мини-«радар» — кольцевая диаграмма, какие факторы сейчас давят на бизнес.
2. **Лента**: фильтры (риски / возможности / фактор / срок), сюжеты вместо дублей, поиск, «прочитано», сортировка по важности/времени.
3. **Карточка инсайта**: hero-вывод, 6 блоков, цветовая маркировка «факт / позиция банка / вывод AI» с легендой, раскрывающиеся цитаты-источники, превью страницы отчёта банка.
4. **Карта влияния** — интерактивная схема «событие → фактор → ваш признак / ваш контрагент → эффект». Лучшая визуализация того, что это не пересказ.
5. **«Что если»** — слайдеры ставки и курса, график эффекта, сравнение с прогнозом банка.
6. **«Как мы видим вашу компанию»** — радар чувствительности, Sankey-схема контрагентов по отраслям, пробелы в данных, возможность поправить («импорта из Китая больше нет») → персонализация меняется.
7. **Ассистент** — боковая панель, стриминг, кликабельные цитаты, ответы с таблицами и мини-графиками, подсказки по контексту.
8. **Дайджест** под роль (день/неделя) + превью письма/push (мок).
9. **Нативные предложения банка**: аккуратная карточка «Зафиксировать ставку», «Валютный форвард» с пометкой «Предложение Альфа-Банка» и причиной, почему именно сейчас.
10. **«Как это работает»** — трассировка агента как таймлайн (шаг, модель, источник, стоимость, время).
11. **Кабинет эксперта банка**: очередь инсайтов на ревью, правка/одобрение тезисов, метрики качества.
12. **Онбординг**: «Мы изучили вашу компанию: 5 факторов, которые для вас важнее всего» + **guided tour для жюри** (сценарий в 7 шагов по кнопке).

Плюс: скелетоны и плавные переходы, адаптив под телефон, доступность (контраст, клавиатура), пустые и ошибочные состояния продуманы.

**DoD:** UX-тест на 3–5 людях вне команды — полный сценарий без подсказок ≤ 3 минут; Lighthouse ≥ 90; макеты ключевых экранов согласованы до вёрстки.

## Этап 8. Безопасность и надёжность

1. Вход по тестовым учёткам (JWT-сессии) вместо заголовка `X-User-Id`, роли, rate limit, CSP и security-заголовки.
2. SSRF-защита загрузки по ссылке: allowlist доменов, запрет приватных IP, лимит размера.
3. **Red-team набор**: 30+ инъекций (в новостях, ссылках, чате, «просьбы» выдать чужие данные) → автотест в CI.
4. Маскирование идентификаторов в логах, политика хранения, бэкапы БД.
5. Наблюдаемость: структурированные логи, Sentry, простой дашборд (Grafana или встроенный), алерты бюджета.
6. Деградация: LLM недоступна → правила; источник упал → метка «источник недоступен»; нагрузочный тест ленты (locust).

**DoD:** red-team 100% зелёный; нагрузочный тест 50 rps без ошибок; описание в `docs/SECURITY.md` со схемой.

## Этап 9. Качество и мониторинг (весь период)

1. Golden set: 300+ пар релевантности, 200 новостей классификации, 50 эталонных инсайтов от эксперта, 40 вопросов к базе знаний банка.
2. В CI на каждый PR: тесты, eval (P@3, nDCG@5, recall@5, F1 классификации, доля прошедших самопроверку) + сравнение с `main` комментарием.
3. Онлайн-метрики в разделе «Качество»: CTR виджета и карточек, 👍/👎 с причинами, вопросы в чате на инсайт, переходы к первоисточнику и продуктам, время до первого вывода, стоимость на инсайт.
4. Цикл улучшения: еженедельный разбор 👎 и выборки экспертом → правка конфигов/промптов → регрессия.

**DoD:** дашборд качества живой; все метрики с целевыми порогами в `docs/QUALITY.md`.

## Этап 10. Сдача и защита

1. Прод прогрет (`manage.py warmup`), демо-учётки стабильны, guided tour работает.
2. Финальный README по шагам (проверить «с нуля» на чистой машине), архитектурная схема картинкой, OpenAPI, THIRD_PARTY_NOTICES актуальны.
3. **Видео-демо 3 минуты** — страховка от сети на защите.
4. Презентация (10–12 слайдов): проблема → решение → живое демо → как работает AI (агент, критик, трассировка) → позиция банка → метрики → безопасность → экономика токенов → масштабирование → дальнейшее развитие.
5. **Живой кейс на защите**: вставить новость дня и показать разбор для двух разных компаний.
6. Тег версии на дедлайн, проверка доступа `alfa-hack-2026`, прогон чек-листа требований (ниже).
7. Репетиции и 20 вероятных вопросов жюри с ответами (почему не пересказ, откуда числа, что при отсутствии позиции банка, сколько стоит, как масштабировать, как защищены данные).

## «Вау»-фичи, на которые делаем ставку

1. **Карта влияния** — видно, как новость доходит до конкретного бизнеса.
2. **Эффект через контрагентов** — «новость не про вас, но про вашего главного покупателя».
3. **«Что если»** со слайдерами и числами банка как базовым сценарием.
4. **Эволюция позиции банка** — как и почему банк менял прогноз.
5. **Сюжеты** вместо дублей — история события во времени.
6. **«Как мы вас видим»** с возможностью поправить профиль.
7. **Прозрачный AI** — трассировка, стоимость, модели, самопроверка на виду.
8. **Дайджест под роль** — финдиректору и главбуху разные акценты.
