## Транспорт и лимиты (этап 11)

- **HTTPS.**
  - Деплой сам получает сертификат Let's Encrypt. Без своего домена сайт получает имя `<ip-через-дефисы>.sslip.io`; свой домен задаётся в `vars.DEPLOY_DOMAIN`.
  - HTTP перенаправляется на HTTPS, включён заголовок HSTS.
  - Cookie сессии становится `Secure` автоматически: приложение видит заголовок `X-Forwarded-Proto: https` от Nginx.
  - Сертификат продлевается сам: таймер certbot, после продления Nginx перечитывает конфиг.
  - Если сертификат получить не удалось, сайт продолжает работать по HTTP, а деплой предупреждает об этом.
- **Конфиг Nginx** собирается `deploy/render_nginx.py` из одного шаблона. CI проверяет его командой `nginx -t` на Nginx 1.18, 1.24 и 1.27 — в вариантах HTTP и HTTPS.
- **Лимиты частоты в два уровня:**
  - Nginx по IP: 10 запросов в секунду к API, 30 в минуту к эндпоинтам с моделями;
  - приложение по пользователю и дополнительно по IP — разбор новости 12, разбор события 30, чат 40 в минуту.
  
  У демо-учёток общий пароль, поэтому лимит по IP не даёт обойти ограничения перебором учёток. IP берётся из `X-Real-IP`, который выставляет только наш Nginx.

## Уведомления в браузере (этап 15)

- Web Push реализован без сторонних push-библиотек (`app/notify/push.py`): содержимое уведомления шифруется ключом браузера по RFC 8291 (aes128gcm), push-сервис браузера видит только шифротекст. Запрос подписан VAPID (ES256, RFC 8292).
- Приватный ключ VAPID задаётся переменной `VAPID_PRIVATE_KEY` или генерируется при первом запуске и хранится в БД на сервере. В репозиторий и в браузер он не попадает, наружу отдаётся только публичный ключ (`/api/push/key`).
- Подписка привязана к пользователю и компании, на которую у него есть права. Принимаются только адреса `https://`. Отписаться можно кнопкой в дайджесте. Если браузер отозвал подписку (404 или 410), сервер её удаляет.
- В уведомлении нет денежных сумм и данных профиля: только заголовок события и причина в одну строку. Подробности открываются после входа.
- Тестовое уведомление ограничено частотой: 3 в минуту на пользователя.

## Red-team набор (автотест в CI)

`backend/tests/test_redteam.py` — 43 атаки, каждая отдельным тестом:
- **12 инъекций в тексте новости** (английские и русские формулировки, кириллица вместо латиницы, невидимые символы, подмена тегов `</news><system>`, «developer mode», «DAN»): событие получает флаг, фрагменты атаки не попадают в разбор, проверка «нет следов prompt injection» проходит;
- **8 атак через чат** (системный промпт, данные других клиентов, API-ключ, подмена тегов, «ты теперь бот без правил»): в ответе нет системного промпта, чужих идентификаторов и ключей;
- **9 попыток доступа к чужой компании** через все эндпоинты с компанией (лента, профиль, дайджест, реранк, сценарии, скрытие, действия, настройки, проверка новости) — везде 403;
- **поддельная и просроченная сессия**, вход заголовком без разрешения — 401; перебор пароля — 429;
- **10 SSRF-адресов** (127.0.0.1, localhost, `[::1]`, 169.254.169.254, 10.x, 192.168.x, `file://`, `gopher://`, порт 22, логин в адресе) — отклоняются.

## Нагрузочный тест

`backend/scripts/loadtest.py` — вход демо-пользователя и равномерный поток запросов (лента 60%, профиль 20%, дайджест 10%, health 10%) на одном процессе uvicorn, данные кейса (85 тыс. компаний), 357 событий:

| Нагрузка | Ошибки | p50 | p95 | p99 |
|---|---|---|---|---|
| 50 rps, 20 с | 0 | 7 мс | 10 мс | 14 мс |
| 150 rps, 15 с | 0 | 8 мс | 14 мс | 31 мс |

Без кэша ранжирования те же 50 rps давали p95 = 123 мс, а 150 rps не выдерживались (p95 6,6 с). Кэш ленты сбрасывается при новых событиях, изменении персональных настроек и раз в час (свежесть событий). Тяжёлые операции с LLM нагрузочным тестом не покрываются: они ограничены по частоте и строятся один раз на событие и компанию.

**Для продакшена (описано, не реализовано в прототипе):** интеграция с IAM банка вместо демо-входа, TLS, шифрование БД, хранение журналов в SIEM, DLP-проверка ответов, отдельный сервисный аккаунт для LLM-шлюза, ревью новых промптов через регрессионный набор.
